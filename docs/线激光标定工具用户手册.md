# 线激光统一标定工具用户手册

> 适用版本：阶段 0～4（PySide6 五步向导）  
> 已验证后端：synthetic；海康 MVS 与大恒 Galaxy USB3 适配器已实现，但仍需各自的 SDK/设备现场验收
> 正式运行约定：`Mono8`、2448 × 2048、统一实时 `steger` 提取链（`shared_steger` 仅为兼容旧配置的别名）
> 文档中的命令默认在本仓库根目录执行；`<...>` 表示需要按现场环境替换的路径。

## 1. 现在能否用这个工具完成标定

可以用于建立和验收一套标定项目，但当前仓库自带的历史快照还没有全部通过正式门禁。当前工具能够完成：

1. 创建并保存标定项目；
2. 连接海康 MVS 或大恒 Galaxy USB3 相机、实时预览、在线调整曝光与增益；
3. 批量采集内参、激光平面、地面外参和补偿数据，并保存 manifest 与哈希；
4. 一次运行相机内参、激光平面、地面外参、地面点云和补偿 workflow；
5. 查看质量门禁、残差、诊断图和补偿前后结果；
6. 生成 `accepted/rejected` 验收报告；
7. 只有验收通过时才发布不可拆分的 calibration bundle。

需要注意两个使用边界：

- 第 3 页既支持加载旧版 `capture-plan` YAML，也支持直接用配方表生成正式的多姿态内参数据和激光三联图；已有旧项目文件无需迁移。
- `configs/workflow.example.yaml` 是结构示例，所有阶段默认 `enabled: false`。必须复制到项目目录、填写实际路径并启用阶段，不能原样点击“一键运行”。

“计算完成”和“正式验收通过”是两个不同结果：

| 结果 | 含义 |
|---|---|
| `Workflow: completed` | 所有已启用标定阶段执行完成，阶段门禁没有失败 |
| `decision: accepted` | workflow、独立验证、补偿、运行配置、golden 和产物全部通过正式验收 |
| `decision: rejected` | 报告已成功生成，但至少有一个质量门禁未关闭，禁止发布 |

当前仓库自带的历史 golden 报告是 `rejected`，这是旧数据存在已知问题，并不表示新项目不能完成标定。

### 1.1 当前软件自检结论（2026-08-08）

| 检查 | 结果 | 解释 |
|---|---|---|
| `python -m calibration_tool --help`、`list-stages` | 通过 | CLI 和 7 个统一 stage 可加载 |
| `camera-list --config configs/camera.example.yaml` | 通过 | synthetic 返回 `SIMULATED-MV-CS050-60GM` |
| `camera-preview`（synthetic） | 可运行，2 帧有 `dynamic_range_low` 告警 | 示例图像动态范围低，应重新调曝光后再做质量验收 |
| `python -m pytest -q` | 83 通过，1 失败 | 失败项为历史 golden snapshot 漂移检查 |
| `golden-check` | `matches: false`，9 项变化 | 外部配置/标定哈希变化或 `camera_intrinsics.yaml` 缺失 |
| `audit` | `overall: fail` | 历史数据缺少独立内参测试、三联图运动闭环、补偿 holdout 等门禁 |

所以“能启动并完成计算”不等于“可以发布生产包”。只有新项目的 workflow、独立验证、运行配置、manifest、golden 和 acceptance report 全部通过，才能继续发布。

## 2. 完整工作流

```mermaid
flowchart LR
    A[固定机械结构与镜头] --> B[曝光摸底]
    B --> C[内参拟合/独立验证]
    C --> D[激光三联图拟合/独立验证]
    D --> E[地面外参拟合/独立验证]
    E --> F[平地激光重建]
    F --> G[偏差表建表/holdout 验证]
    G --> H[验收报告]
    H -->|accepted| I[发布 calibration bundle]
    H -->|rejected| J[查看失败门禁并补采/重算]
```

一套正式标定至少应包含以下相互独立的数据：

| 数据组 | 推荐数量 | 激光 | 用途 |
|---|---:|---|---|
| 内参拟合集 | 15～25 个不同姿态 | 关闭 | 拟合相机内参与畸变 |
| 内参验证集 | 5 个不同姿态 | 关闭 | 完全独立的重投影验证 |
| 激光平面拟合集 | 12～18 组三联图 | 按帧切换 | 拟合激光平面 |
| 激光平面验证集 | 4～6 组三联图 | 按帧切换 | 独立验证平面误差 |
| 地面外参拟合集 | ≥ 6 张同一基准平面的棋盘图 | 关闭 | 相机坐标系到地面坐标系 |
| 地面外参验证集 | ≥ 2 张 | 关闭 | 独立验证地面外参 |
| 平地补偿数据 | 建表 ≥ 8，建议 20；验证 ≥ 2，建议 5 | 开启 | 生成逐列偏差表并 holdout 验证 |
| 障碍物验收数据 | ≥ 3 张 | 开启 | 端到端三维恢复检查 |

上表“推荐数量”不是简单追求越多越好。重复、模糊或集中在同一位置的图像不能替代姿态多样性。

## 3. 标定前准备

### 3.1 硬件状态

开始采集前逐项确认：

- 相机、镜头、线激光器和支架已经最终固定；
- 镜头焦距、对焦环和光圈已固定，后续不会再旋转；
- 棋盘格平整、无翘曲，方格实际尺寸已用可靠量具确认；
- 棋盘参数填写的是“内角点数量”，不是黑白方格数量；
- 相机网络连接稳定，MVS 客户端和标定工具不会同时占用相机；
- 正式运行若使用 Mono8，则正式标定也统一使用 Mono8；
- ROI、分辨率、PixelFormat 在整套正式数据中保持一致；
- 增益建议保持 `0 dB`，优先通过曝光和现场遮光改善信噪比。

以下变化会使现有标定失效，发生后必须重新标定：

- 相机或激光器位置/角度变化；
- 镜头焦距、对焦或光圈变化；
- 分辨率、ROI、Offset 变化；
- 正式提取器从统一实时 `steger` 改为其他算法；`shared_steger` 与 `steger` 在当前版本中等价；
- 相机、镜头或激光器被替换。

### 3.2 软件自检

在 PowerShell 中执行：

```powershell
cd <标定工具项目目录>

python -m calibration_tool golden-check
python -m calibration_tool camera-list --config configs\camera.example.yaml
```

无硬件时先确认 synthetic 链路：

- `camera-list` 应返回 `SIMULATED-MV-CS050-60GM` 和 `SIM-001`；
- `camera-preview` 可以完成取流，但示例配置可能出现 `dynamic_range_low`，应调整曝光后再判断质量；
- `golden-check` 在当前仓库历史快照上预期为 `matches: false`，这表示 9 项配置/标定哈希或文件状态漂移，不能直接覆盖 baseline。

接入海康真机时使用 `camera.mvs.example.yaml`。接入大恒真机时使用 `camera.daheng.example.yaml`，确认 Galaxy SDK、Python/SDK 位数、设备型号和序列号后再运行 `camera-list`。若厂商客户端正在取流，应先停止并断开相机，再运行标定向导。

完整测试可执行：

```powershell
python -m pytest -q
```

当前快照为 83 个测试通过、1 个 golden snapshot 失败；失败来自历史 baseline 漂移，而不是 CLI 导入失败。

### 3.3 启动向导

真机模式：

```powershell
cd <标定工具项目目录>
python -m calibration_tool gui --project configs\wizard_project.example.yaml
```

无相机演练模式：

```powershell
python -m calibration_tool gui --simulate
```

## 5. 第 2 步：连接相机并确定曝光

![相机与曝光页面](images/user_manual/02_camera.png)

### 5.1 连接与取流

1. 确认“相机配置”指向项目的 `camera.yaml`，点击“加载”。
2. 点击“枚举相机”，从设备下拉框确认型号和序列号。
3. 正式运行使用 Mono8 时，将“像素格式”设为 `Mono8`。
4. 确认 `Offset X/Y = 0`、宽度 `2448`、高度 `2048`，或填写最终运行时完全一致的 ROI。
5. 选择当前要观察的“质量模式”。
6. 点击“开始取流”。状态应显示实际型号、序列号和分辨率。

### 5.2 在线修改曝光

- 取流期间可以修改“曝光”和“增益”，然后点击“应用曝光/增益”。
- 状态文字出现“相机回读：曝光 …，增益 …”后，才表示参数真正生效。
- 工具会丢弃 2 帧旧参数图像，因此画面不会使用切换前的缓存帧。
- PixelFormat、Offset、宽度和高度会改变数据格式或成像几何，取流期间被禁用。必须先点击“停止”，修改后重新取流。

“自动拉伸预览”只改变屏幕显示，不改变曝光、原始 DN 或保存文件。正式选择曝光时应关闭自动拉伸，并以质量指标和原始图为准。

### 5.3 三种质量模式

| 模式 | 使用场景 | 检查内容 |
|---|---|---|
| 棋盘格 | 内参、棋盘参考帧，激光关闭 | 过曝、欠曝、动态范围、完整内角点检测 |
| 激光线 | 激光帧、平地帧、障碍物帧 | 激光对比度、横向覆盖率、过曝、动态范围 |
| 通用曝光 | 无激光低曝光背景帧 | 过曝、欠曝、动态范围 |

肉眼看到棋盘但显示“未找到完整棋盘”时，按以下顺序检查：

1. 实物是否真的是 `11 × 8` 个内角点；
2. 棋盘最外圈是否完整入镜；
3. 激光是否穿过角点；内参图必须关闭激光；
4. 是否失焦、运动模糊、反光或曝光过暗；
5. 将棋盘移动到画面中央，并减少过大的透视倾斜；
6. 不要用“自动拉伸预览”掩盖原图曝光不足。

### 5.4 大恒相机

大恒相机使用独立的 `daheng` backend 和 `camera.daheng.example.yaml`，不能复用海康的 `backend: mvs`。适配器复用现有 `CameraProvider`/`CameraSession` 接口，GUI、预览和采集计划无需使用另一套流程。

`gxipy` 随完整 Galaxy SDK 安装，默认搜索 `C:\Program Files\Daheng Imaging\GalaxySDK`。非默认安装位置设置 `DAHENG_GALAXY_ROOT`；仅需指定 Python wrapper 时可设置 `DAHENG_GALAXY_PYTHON_PATH`。当前只枚举 USB3 Vision 设备并按序列号打开；多台设备时必须填写 `serial_number`。真机现场还需确认 USB3 链路、触发模式、Mono8/Mono12 回读和连续取流稳定性。

```powershell
python -m calibration_tool camera-list --config configs\camera.daheng.example.yaml
python -m calibration_tool camera-preview --config configs\camera.daheng.example.yaml
```

### 5.5 曝光摸底

同一姿态依次测试三类曝光，期间不要移动棋盘或相机：

| 图像 | 激光状态 | 可从以下范围开始测试 | 模式 |
|---|---|---:|---|
| 棋盘参考图 | 关闭 | 15000、20000、30000、40000、50000 μs | 棋盘格 |
| 低曝光背景图 | 关闭 | 150、200、300、400、800、1200 μs | 通用曝光 |
| 激光图 | 开启 | 150、200、300、400、800、1200 μs | 激光线 |

曝光范围只是当前现场的起点。最终选择应满足：

- 棋盘完整内角点连续多帧稳定通过；
- 激光中心清晰但不能形成大面积饱和带；
- 激光横向覆盖满足使用区域；
- 增益尽量为 0 dB；
- 同类正式采集使用固定曝光，不在一组拟合数据中混用随意曝光。

## 6. 第 3 步：采集标定数据

![批量采集页面](images/user_manual/03_capture.png)

### 6.1 页面操作

1. 填写一个尚不存在的“输出数据集”目录。工具拒绝覆盖已完成数据集。
2. 填写唯一“数据集 ID”。
3. 选择 `tif` 或 `png`（正式标定默认 `tif`），设置拟合集、起始编号、编号位数和可选验证集。
4. 在每组图像配方表中修改启用状态、曝光、文件前缀、激光提示、质量模式、帧数和稳定帧；需要时点击“恢复三联图默认值”。
5. 点击“生成并检查计划”，确认任务预览和统计信息。
6. 点击“开始采集”；正式三联图每个姿态按 chess→laser→nolaser 完成后才移动到下一姿态。

当前 PySide6 向导的推荐完整操作顺序是：先在第 1 页应用项目并在第 2 页确认相机；在第 3 页填写数据集 ID、输出目录和计划 YAML 路径，点击“生成并检查计划”后计划会自动保存到数据集目录之外（例如 `projects/default/plans/laser_plane.yaml`），并立即用 `load_capture_plan()` 做 round-trip 校验。默认三联图写入 `projects/default/data/laser_plane/fit` 和 `projects/default/data/laser_plane/validation`，文件名为 `chess 001.tif`、`laser 001.tif`、`nolaser 001.tif`。默认 `nolaser`/`laser` 曝光为 500 μs。

点击“开始采集”后，页面会自动切换到第一个未完成任务并启动持续实时预览。准备好当前任务后点击“采集当前任务全部帧”，工具先在当前任务参数下丢弃一次 `settle_frames` 预热帧，再连续保存该 task 的全部剩余帧；连续保存期间不再重复丢弃，采满后自动在线应用下一个任务的曝光、增益和质量模式。实时画面管道保持连接；只有 ROI 或像素格式等结构性参数改变时才会执行必要的停流重配。三联图完成一组后再移动棋盘。页面中的“取消”会停止预览并保留 `.inprogress` 数据集；下次保持计划不变，勾选“续采”即可继续，续采仍会校验原计划 hash。采集成功后页面会记录 plan、数据集根目录、fit/validation、`dataset_manifest.yaml` 和 `frames.csv`，并写入项目 YAML 的 `extra.capture_artifacts`（旧项目字段仍兼容）。

连续多帧引导采集时，`dataset_manifest.yaml` 每帧更新，是断点续采的事实来源；`frames.csv` 在当前 task 采满时一次性刷新。这样可以避免 Windows 对同一个 CSV 的高频文件替换产生共享冲突，同时不会降低逐帧续采能力。

按钮分工：上排“预览选中任务”用于在正式采集前试看所选任务的曝光和实时画面；“采集当前任务全部帧”是唯一的保存入口，一次采满当前 task 的全部剩余帧后自动切换下一任务；“下一任务”只用于手动改变预览选择。下排“开始采集”启动逐任务实时引导，“续采”从 `.inprogress` 的首个未完成任务启动，“取消”停止当前引导并释放相机。

每个完成的数据集都包含：

- 原始图像；
- `dataset_manifest.yaml`；
- `frames.csv`；
- 请求参数和相机实际回读参数；
- 设备身份、帧号、时间戳和 SHA-256；
- 每帧曝光、清晰度、棋盘或激光质量结果。

如果采集中断，现场保存在同级的 `.<数据集名>.inprogress`。修复连接后勾选“续采对应的 .inprogress 数据集”，并保持原计划完全不变。

### 6.1.1 从采集结果进入标定

1. 采集完成后进入第 4 页，点击“从最近采集结果更新 Workflow 输入”。
2. 先查看预览；向导只替换已有 stage options 中的 `fit_dir`、`test_dir` 或 `validation_dir` 等输入路径，不修改内参、激光面算法和质量阈值。
3. 确认后工具先生成 `.bak` 备份，再以原子方式写回 workflow。验证集未勾选时不会强行写入不存在的 validation 目录。
4. 点击“检查 Workflow 阶段”，确认输入、输出目录和启用状态后，再点击“一键运行完整标定”。
5. 标定完成后进入第 5 页。工具会把完整 workflow 转换为 `CalibrationRun`，在共同 run 目录写入 `calibration_run.yaml`，并把路径记录到已保存项目的 `last_calibration_run`。
6. 第 5 页提供“结果总览”“相机内参”“激光表面”“地面外参”四个页签。页面只读取已有结果和诊断图，不重新计算标定；缺少阶段或文件时显示“未执行”“暂无”或明确错误。需要查看旧结果时点击“打开历史标定结果…”，可加载 `calibration_run.yaml`，也兼容旧 `workflow_*.yaml`。

### 6.2 内参数据

1. 关闭激光。
2. 选择棋盘格质量模式和选定的棋盘曝光。
3. 采集 15～25 个拟合姿态，覆盖画面中央、四角和边缘。
4. 同时包含轻微俯仰、偏航、横滚及远近变化，避免所有棋盘都与成像面平行。
5. 再采集至少 5 个完全不同的验证姿态，验证图绝不能复制到拟合集。
6. 所有图必须找到完整内角点；模糊、反光或裁边图应重新采集。

### 6.3 激光平面三联图

每个姿态必须连续采集以下三张图：

```text
chess 001.tif    高曝光、激光关闭，用于棋盘位姿和运动参考
laser 001.tif    低曝光、激光开启，用于激光中心和可用时的运动匹配
nolaser 001.tif  相同低曝光、激光关闭，仅用作背景扣除
```

运动检查的参考图是高曝光 `chess`，不是 `nolaser`。`nolaser`与`laser`必须保持相同短曝光，才能正确扣除背景；在该曝光下棋盘不可见是正常现象。若 `laser` 图只包含激光线、没有足够棋盘纹理，工具会报告 `unresolved_low_texture`，这表示“无法从图像测量”，不等于检测到位移。

最重要的规则是：三张图之间棋盘、相机和支架不能发生任何移动。

推荐操作顺序：

1. 固定第 001 个棋盘姿态并等待支架稳定。
2. 激光关闭，使用棋盘曝光采集 `chess 001.tif`。
3. 不接触棋盘，改为低曝光并打开激光，采集 `laser 001.tif`。
4. 保持低曝光、关闭激光，不移动其他部件，采集 `nolaser 001.tif`。
5. 完成三张后再移动棋盘进入下一个姿态。
6. 拟合集建议 12～18 组；另采 4～6 组独立验证集。

若 `pair_motion_diagnostics.csv` 报告 `median_displacement_px > 1.0`，这是可测量的真实位移，必须删除该组并重新采集；若 `movement_method=unresolved_low_texture`，只表示短曝光目标没有足够棋盘纹理，质量门禁会给出警告，需人工确认三张图之间没有移动。当前三联图格式若要实现自动闭环判定，需要把与 `chess` 同曝光的 tracking 图作为第四帧接入运动检查；不能依靠几乎全黑的 `nolaser` 图。

### 6.4 地面外参数据

本工具推荐使用 `ground_extrinsics_board_only`：

1. 将棋盘刚性放置在最终定义的地面基准平面上。
2. 关闭激光，使用棋盘曝光。
3. 拟合集至少采集 6 张，棋盘在同一物理平面上改变平面内位置和方向。
4. 验证集至少 2 张，不能参与拟合。
5. 不要垫高棋盘或使用明显翘曲的板面；棋盘表面就是该方法定义的 `Z=0` 基准面。

### 6.5 平地补偿与端到端验证数据

1. 移除棋盘和障碍物，保持最终地面基准区域平整。
2. 打开激光，使用最终运行曝光。
3. 建议采集 20～30 帧独立平地图像。
4. workflow 中用 `validation_count` 保留最后 5 帧作为 holdout；这些帧不能参与补偿表建表。
5. 另外放置已知高度或可测量尺寸的障碍物，采集至少 3 张端到端验证图。

正式补偿必须满足：

```text
evaluation_frame_count > 0
build_frame_count + evaluation_frame_count == loaded_frame_count
```

把 `validation_count` 设为 0 会被正式验收拒绝，即使补偿后残差看起来非常小。

### 6.6 第 3 页的单姿态边界

第 3 页每次创建一个完整、不可覆盖的数据集。因此：

- 曝光摸底和单姿态快速采集可直接使用第 3 页；
- 多姿态正式数据若反复使用第 3 页，每个姿态必须使用不同输出目录；
- 激光三联图还需要保证文件命名和目录能被 workflow 的 `chess_pattern/nolaser_pattern/laser_pattern` 匹配；
- 为减少人工整理和重命名，正式采集推荐使用下一节的多任务 YAML。

加载 `capture-plan` 后，第 3 页也支持逐任务引导采集，不需要在第 2 页和第 3 页之间来回切换：

- “预览选中任务”和“下一任务”会应用该 task 的曝光、增益、ROI、像素格式和质量模式，并在第 3 页显示实时画面、棋盘检测提示、激光指标和相机实际回读参数；
- 任务切换后立即显示实时预览；点击“采集当前任务全部帧”时，先按该 task 的 `settle_frames` 丢弃一次预热帧；
- 预热完成后连续保存该 task 的全部剩余帧；同一 task 内不再重复丢弃预热帧；
- 采集过程中可以直接观察棋盘是否完整入镜、内角点是否检测通过，以及激光覆盖率和饱和告警。`frames > 1` 的 task 只需点击一次，采满后自动切换下一任务。

### 6.8 统一实时 Steger 参数

标定和在线测量共用：

```text
calibration/config/realtime_steger.yaml
```

当前默认值为 `sigma=1.5 px`。若激光横截面 FWHM 约为 2～3 px，可先用 `1.5`，再在 `1.2/1.5/1.8/2.0` 做一组验证；不要把 `sigma` 机械地设成 FWHM。经验关系 `sigma_line ≈ FWHM/2.355` 只适用于近似高斯、未饱和的线，Steger 的导数尺度还要兼顾噪声和亚像素稳定性。

修改 profile 后重新运行标定，并把同一文件用于在线工具；`steger` 与历史 `shared_steger` 配置名最终调用同一个 extractor。每份输出的 `centre_extraction`/`extraction` 元数据会记录实际 `sigma`，便于追溯。

### 7.3 质量门禁

| 阶段 | 必须满足的默认门禁 |
|---|---|
| 内参 | 拟合 RMSE ≤ 0.30 px；独立测试图 ≥ 1；测试 RMSE ≤ 0.50 px |
| 激光平面 | 独立验证 RMSE ≤ 0.25 mm；P95 ≤ 0.50 mm；三联图无未排除运动 |
| 棋盘地面外参 | 独立验证 RMSE ≤ 0.20 mm |
| 混合地面外参（若使用） | `ground_z_std_passed = true` |
| 地面补偿 | 至少 1 帧完全独立的 holdout 验证 |

任一门禁失败时，workflow 会停止并保留已生成的诊断文件。应根据失败项补采或修正配置，不应直接使用 `allow_quality_failure` 绕过正式标定。

| 指标 | 要求 |
|---|---:|

| P–V 降幅 | ≥ 80% |
| RMS 降幅 | ≥ 80% |

### 11.1 先确认包格式

验收发布出来的标定包就是第 10 节中的 release 目录。需要注意两点：

1. 发布包中的文件名来自 `config/runtime.yaml` 里 `calibration` 段实际指向的源文件名。因此，如果内参源文件是 `calibration_result.yaml`，包里就是 `calibration_result.yaml`；如果源文件已整理成 `camera_intrinsics.yaml`，包里就是 `camera_intrinsics.yaml`。

```text

├─ laser_plane.yaml

├─ ground_bias_table.npy

└─ acceptance_report.html
```

```text
├─ laser_plane.yaml
```

`ground_bias_table.npy` 可以直接被 0704 加载；如果你同时发布了 `ground_bias_table.csv`，也可以改用 CSV，并在 manifest 和 `measure_tool.yaml` 中保持同一个文件名。

假设新发布包为：

```text
<标定工具项目目录>\projects\<project-id>\releases\<package-id>
```

把发布包里的运行必需文件复制到 0704 的 `configs/calibration/`：

```powershell
$release = "<标定工具项目目录>\projects\<project-id>\releases\<package-id>"
$target = "<实时测量工具目录>\configs\calibration"

Copy-Item "$release\calibration_result.yaml" "$target\calibration_result.yaml" -Force
Copy-Item "$release\laser_plane.yaml" "$target\laser_plane.yaml" -Force
Copy-Item "$release\camera_ground_extrinsics.yaml" "$target\camera_ground_extrinsics.yaml" -Force
Copy-Item "$release\ground_bias_table.npy" "$target\ground_bias_table.npy" -Force
Copy-Item "<标定工具项目目录>\calibration\config\realtime_steger.yaml" "$target\realtime_steger.yaml" -Force
```

然后在 `$target\manifest.yaml` 中写入 0704 在线工具需要的 runtime manifest。`camera` 信息应与本次标定时的相机、分辨率、ROI 保持一致；`extractor.algorithm` 使用 `steger`（历史包中的 `shared_steger` 仍兼容）：

```yaml
schema_version: 1
package_id: <package-id>
camera:
  model: MV-CS050-60GM
  image_width: 2448
  image_height: 2048
extractor:
  algorithm: steger
  settings:
    sigma: 1.5
    threshold: 30.0
    deriv_thresh: 0.5
    roi_margin: 120
    roi_max_height: 512
    scan_axis: column
files:
  intrinsics:
    path: calibration_result.yaml
    sha256: <填 calibration_result.yaml 的 sha256>
  laser_plane:
    path: laser_plane.yaml
    sha256: <填 laser_plane.yaml 的 sha256>
  extrinsics:
    path: camera_ground_extrinsics.yaml
    sha256: <填 camera_ground_extrinsics.yaml 的 sha256>
  ground_u_compensation:
    path: ground_bias_table.npy
    sha256: <填 ground_bias_table.npy 的 sha256>
quality:
  acceptance_decision: accepted
```

哈希值必须与 0704 加载器一致：它会把文本文件的 CRLF 归一化为 LF 后计算 SHA-256。推荐用下面这段命令计算，再填回 `manifest.yaml`：

```powershell
cd <实时测量工具目录>

python -c "from pathlib import Path; import hashlib; root=Path('configs/calibration'); names=['calibration_result.yaml','laser_plane.yaml','camera_ground_extrinsics.yaml','ground_bias_table.npy']; [print(n, hashlib.sha256((root/n).read_bytes().replace(b'\r\n', b'\n')).hexdigest()) for n in names]"
```

### 11.4 修改 0704 的运行配置

打开：

```text
<实时测量工具目录>\configs\measure_tool.yaml
```

把 `calibration` 段改成指向新文件。相对路径都是相对于 `configs/measure_tool.yaml` 所在目录解析：

```yaml
calibration:
  manifest: calibration/manifest.yaml
  intrinsics: calibration/calibration_result.yaml
  laser_plane: calibration/laser_plane.yaml
  extrinsics: calibration/camera_ground_extrinsics.yaml
  ground_u_compensation: calibration/ground_bias_table.npy
```

同时把默认提取算法切到与标定链一致的实时 `steger`，并让在线工具读取随标定包复制过去的 profile。需要调整 `sigma` 等参数时，先在标定工具内验证，再重新复制该文件，避免在线仓库依赖标定工具所在的机器路径：

```yaml
extraction:
  method: steger
  profile: calibration/realtime_steger.yaml
  steger: {}
```

如果要保留旧配置，推荐另存为 `configs/measure_tool_<package-id>.yaml`，启动时用 `--config` 指定。

### 11.5 启动并验证

单帧测量工具：

```powershell
cd <实时测量工具目录>
python main.py --config configs\measure_tool.yaml
```

在线相机程序：

```powershell
python online_camera.py --config configs\measure_tool.yaml
```

启动阶段如果 `manifest.yaml` 缺少必需文件、哈希不一致、`extractor.algorithm` 不是 `steger` 或兼容别名 `shared_steger`，在线程序会直接报错。启动成功后，用平地样张或在线平地画面做一次重建检查：

- 图像 ROI、分辨率、PixelFormat 必须与标定时一致；
- `calibration_package_id` 应显示新 `<package-id>`；
- 平地重建后的 `Zg` 应接近 0，补偿方向为 `Zg_corrected = Zg_raw - bias(u)`；
- 若结果整体偏高或偏低，先检查是否用了旧 `manifest.yaml`、旧 `measure_tool.yaml` 或错误的地面补偿文件，不要先改外参符号。

## 12. 常见问题排查

| 现象 | 原因 | 处理方法 |
|---|---|---|
| 能看到棋盘但 `chessboard_not_found` | 内角点配置错误、裁边、激光遮挡、模糊或反光 | 关闭激光，确认 11×8 内角点，完整入镜并重新调曝光/对焦 |
| 修改曝光后画面不变 | 参数尚未写入或仍在显示旧帧 | 点击“应用曝光/增益”，等待状态显示相机回读值 |
| Mono12 看起来比 MVS 客户端亮/暗 | 显示映射或自动拉伸不同 | 关闭自动拉伸，比较原始 DN 和相同位深；正式运行 Mono8 就统一使用 Mono8 |
| 输出目录非空，拒绝覆盖 | 工具保护旧结果 | 使用新的 run/package ID；确认无用后由用户自行归档旧目录 |
| 发现 `.inprogress` | 上次采集中断 | 保持计划不变，勾选续采或使用 `--resume` |
| 内参独立测试失败 | 验证姿态不足或与拟合集重复 | 重新采集完全独立、清晰、覆盖不同区域的验证图 |
| `pair_motion` 报 `pair_movement` | 三联图之间检测到可测量位移（>1 px） | 固定支架，按 chess→laser→nolaser 顺序重新采集该组 |
| `pair_motion` 报 `unresolved_low_texture` | 短曝光 `laser` 图没有足够棋盘纹理，无法自动测量 | 先人工确认三张图未移动；需要自动判定时把同曝光 tracking 图作为第四帧接入 |
| 地面补偿独立验证失败 | `validation_count=0` 或建表/验证帧混用 | 保留至少 2 帧，建议 5 帧 holdout |
| extractor mismatch | runtime config 与标定链算法不一致 | 全链统一使用实时 `steger`，不要只改报告字段 |
| `rejected` 但补偿指标很好 | 其他阶段仍有 fail | 查看 HTML/CSV 中具体失败项；补偿通过不能替代内参、激光平面或外参验收 |

## 13. 最终验收清单

在把标定包交给运行工具前，逐项签认：

- [ ] 相机、镜头和激光器已经最终固定；
- [ ] 正式采集与运行均使用 Mono8、相同 ROI 和分辨率；
- [ ] 棋盘规格确认是 11×8 内角点、20 mm 实测方格；
- [ ] 内参拟合与验证数据完全分离；
- [ ] 激光平面拟合与验证三联图完全分离；
- [ ] 三联图没有 `pair_movement`（>1 px）；`unresolved_low_texture` 警告已人工确认未发生移动；
- [ ] 地面外参有独立验证；
- [ ] 补偿至少保留 2 帧、建议 5 帧 holdout；
- [ ] workflow 为 `completed`；若仅有已人工确认的 `unresolved_low_texture`，允许 `overall: warn`，不得有 `fail`；
- [ ] runtime config 的提取器为 `steger`（旧 `shared_steger` 仅作为兼容别名）；
- [ ] acceptance report 为 `accepted` 且 `FAIL 0`；
- [ ] 发布包 manifest 中没有 `release_override: true`；
- [ ] 发布包和原始采集 manifest 已归档，能够追溯文件 SHA-256。

只有以上项目全部满足，才能把该标定包视为可用于正式测量的完整标定结果。
