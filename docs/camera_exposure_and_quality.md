# 相机曝光、位深与质量筛查逻辑

## 1. 当前取流参数流程

1. 加载 `camera.mvs.example.yaml`，参数只进入界面控件，尚未写入相机；
2. 点击“开始取流”后，MVS adapter 独占打开相机，关闭自动曝光/自动增益，写入
   PixelFormat、ExposureTime、Gain 和 ROI，并读取相机实际接受值；
3. 开始连续取流并丢弃 3 帧，避免显示打开相机前残留的数据；
4. 取流期间修改曝光或增益时，参数请求被投递到相机取流线程；该线程在两帧之间写入
   ExposureTime/Gain、读取实际值，再丢弃 2 帧旧参数图像；
5. PixelFormat、Offset、Width/Height 会改变数据格式或成像几何，取流期间禁用，必须停止后修改；
6. 批量采集的 manifest 同时保存请求参数和相机回读参数。

因此，界面控件中的数值不再被当作“已经生效”；只有状态栏显示的“相机回读”才代表当前实际值。

## 2. Mono8 与 Mono12

曝光时间决定传感器收集光子的时长，Mono8/Mono12 决定输出 DN 的量化位数：

| 项目 | Mono8 | Mono12 |
|---|---:|---:|
| 原始 DN 范围 | 0–255 | 0–4095 |
| 单帧数据量 | 较小 | 约为 Mono8 的两倍 |
| 暗部量化 | 较粗 | 更细 |
| 正式运行计划 | 是 | 否 |

向导默认使用固定量程显示：Mono8 的 0–255 和 Mono12 的 0–4095 都线性映射到屏幕
0–255。“自动拉伸预览”按当前帧分位数重新映射，只适合观察暗部，不代表曝光变亮，保存的原始数据也不会改变。

相机几何在同一 ROI、分辨率、镜头和焦距下理论上不因位深改变，但棋盘角点和激光中心会受量化、
饱和与算法阈值影响。正式运行若使用 Mono8，推荐全部正式标定和验证也使用 Mono8。已有 Mono12
内参不一定立即失效，但必须用 Mono8 独立验证；激光平面、地面外参及补偿数据不要跨位深混用。

## 3. 三种质量模式

### 通用曝光

- `saturation_fraction`：达到传感器量程 99.5% 的像素比例；
- `dark_fraction`：低于量程 2% 的像素比例；
- `dynamic_range_u8`：P99−P1，并归一化为 8-bit DN；
- `focus_laplacian`：8-bit 固定量程图的 Laplacian 方差，仅报告，不使用一个跨场景硬阈值。

### 激光线

- 允许绝大部分背景为暗像素，不使用全局暗像素比例判失败；
- 动态范围使用 P99.9−P1，避免窄激光线被 P99 忽略；
- 每列比较峰值与中位背景，统计有足够激光对比度的列占比；
- 当前默认要求横向覆盖率至少 30%，同时检查过曝和动态范围。

### 棋盘格

- 先执行通用曝光检查；
- 对用于检测的副本做对比度增强和适度缩放，不修改原图；
- 依次尝试经典 OpenCV 检测和 `findChessboardCornersSB`；
- 检查配置的内角点数量，并额外尝试行列互换以诊断配置错误；
- 若检测到贯穿画面的水平强激光线，会在诊断副本上抑制该线再次尝试，从而区分
  “激光遮挡棋盘”和普通“未找到棋盘”。

能用肉眼看到黑白格，不代表算法能找到**完整且数量正确的内角点**。常见失败原因包括：激光线穿过角点、
配置的 11×8 与实际内角点数量不一致、棋盘边缘没有完整入镜、运动模糊、失焦、反光或曝光不足。

## 4. 推荐采集方式

- 相机内参：Mono8，关闭激光，使用棋盘格模式；调曝光直到完整角点稳定通过且不过曝；
- 激光平面：棋盘参考帧关闭激光并验证角点，激光帧打开激光并使用激光线模式；所有帧保持相同
  PixelFormat、ROI、镜头和焦距；
- 地面外参和运行验证：使用与正式运行相同的 Mono8、ROI、中心提取器及接近运行条件的曝光；
- “自动拉伸预览”可用于构图和排障，但曝光选择以原始 DN 质量指标为准。
